Salesforce Transfer

Bring new Salesforce records into the Sensor Network Tracker. Nothing is saved until you click Approve, and only records created since the last transfer are shown.

How to do a Salesforce transfer, start to finish

For anyone doing this for the first time. It starts in Salesforce (getting the data out) and ends here (reviewing it into the app). No software to install; everything happens in a web browser (Chrome or Edge).

Before you start

  • You need: an admin account in the Sensor Network Tracker (with your authenticator app for the 6-digit code), and someone with Salesforce admin access for steps 1 and 2 (that can be you).
  • Time: Salesforce takes anywhere from a few minutes to a day to prepare the export. Reviewing takes roughly an hour or two per few hundred records. You can stop and come back anytime.
  • Safety: nothing is added to the app until you click Approve on a record, and the page never changes or moves existing sensors, communities, or notes.

1 Ask Salesforce for an export

  1. Sign in to Salesforce. Click the gear icon (top right) → Setup.
  2. In the Quick Find box (top left), type Data Export and click Data Export.
  3. Click Export Now.
  4. Set these options:
    • Export File Encoding: choose Unicode (UTF-8) so names with special characters come through correctly.
    • Tick Include Salesforce Files and Salesforce CRM Content document versions. This brings the full text of longer notes.
    • Leave Include images, documents, and attachments unticked. Attachments aren't transferred, and they make the download huge.
    • Leave Replace carriage returns with spaces unticked (keeps line breaks in notes).
    • Under Exported Data, tick Include all data.
  5. Click Start Export.
"Export Now" missing or greyed out? Salesforce only allows one export every 7 days (29 days on some plans). The Data Export page shows when the next one is allowed. If a recent export is listed there, you can use it if it's new enough.

2 Download the ZIP file

  1. Salesforce emails you when the export is ready. Go back to Setup → Data Export.
  2. Click download next to the file. Its name starts with WE_ and ends in .ZIP.
  3. Save it somewhere easy to find, like Downloads. Don't unzip it; this page reads the ZIP as is.
Download it promptly: Salesforce deletes export files after about 48 hours. If there are several ZIP files (big exports get split), use the first one (ending in _1.ZIP); that's the one with the data tables.

3 Sign in on this page

Below this guide, sign in with your normal Sensor Network Tracker email and password, then the 6-digit code from your authenticator app. If you're already signed in to the app in this browser, this step is skipped.

4 Choose the ZIP

Click the box (or drag the ZIP onto it) and choose the file from step 2. It's read inside your browser; nothing is uploaded anywhere. A big export can take a minute or two.

5 Check the date at the top

The bar at the top says "Showing Salesforce records created after [date]". The page fills it in for you: with a newer export, it starts where the previous transfer ended, and if you come back to the same export, it picks up where you left off. The note next to the date explains which. Only change it if you know the last transfer covered a different period.

Anything already in the app from an earlier transfer is always hidden, whatever the date says.

6 New sensors and new contacts (top of the left list)

  • New sensors: pods in Salesforce that aren't in the app yet. Check the type and community, then click Create (or Create all). Retired pods are added as archived.
  • New contacts: people in Salesforce who aren't in the app. Create the ones you want to keep.

You can skip this step: if a record you approve needs a new sensor or contact, it's created then. New communities are never created; if one is missing, add it in the app first.

7 Review the records, one community at a time

Click a community on the left. Each record is a card that's ready to go: copies of the same event are already combined into one card, and sensors mentioned in the text (like "mod 665 audited by mod 471") are already tagged. For each card:

ApproveSaves it to the app right away.
SkipYou don't want it (junk, test, not useful). It's hidden.
⚠ Possibly already in the appSomeone may have typed this into the app by hand. The box shows the app's entry. Same thing? Skip. Different? Approve anyway.
Approve all N hereApproves every remaining card in that community except ⚠ ones.
UndoRemoves an approved record from the app again (only until you close this page; after that, delete it in the app).
Edit anythingType, date, text, and tags can all be changed before approving. Use → Make it a note / communication if it's the wrong kind.
? Account nameRecords from a Salesforce account that didn't match a community. Pick the community at the top of that list.
First time? Approve one card, then open the app in another tab and find it (the sensor's or community's page). Imported records show "Created by [Salesforce author], SF import"; audits appear under the sensor's Audits section. Once it looks right, carry on.

8 Finish up

  • You're done when every community on the left shows ✓. You can stop partway: open this page again later, choose the same ZIP, and only what's left appears.
  • Delete the ZIP file from your computer (and empty the Recycle Bin) when you're finished. It contains everyone's contact details.

If something goes wrong

Sign-in failsUse the same email/password as the app. The code changes every 30 seconds, so use the current one. Not an admin? Ask an admin to change your role in the app's Settings.
"doesn't contain ... data"Wrong ZIP. Choose the WE_..._1.ZIP file from Salesforce, not an unzipped folder or a different file.
"couldn't be read as a ZIP"The download didn't finish. Download it again from Setup → Data Export.
Error when approvingThe red message says why (often: pick a community first). Nothing half-saved is left behind.
Page is stuckRefresh the browser (Ctrl+F5) and choose the ZIP again. Everything you approved is safe in the app.
